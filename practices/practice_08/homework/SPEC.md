# Интерфейс ревью изменений

## Пользовательский сценарий

Разработчик перед коммитом вставляет `git diff`, отправляет на ревью и
получает комментарий существующего сервиса. Он может исправить текст,
повторить запрос после ошибки или посмотреть инструкцию получения diff.

Прототип: `design/prototype.html` (HTML/CSS/JavaScript, создан Codex).
В переключателе доступны исходный экран, ввод, загрузка, результат,
пустой ответ и ошибка. Прототип не вызывает API и помечен соответствующе.

## Сохранённый API

- Используется `create_app` и `ReviewService` из практики 5.
- `POST /api/reviews`, запрос `{"diff": "..."}`, ответ `{"comment": "..."}`.
- Непустая строка до 20 000 символов; пробельная строка запрещена.
- Принимается ровно 20 000 символов; 20 001 отклоняется до модели.
- Текст запроса не обрезается и не нормализуется, длина соответствует
  Python `len` (Unicode code points).
- В тестах HTTP подменён; реальная демонстрация использует Ollama.
- Новый адаптер Ollama только подключает модель к существующему сервису.
  Реализация и правила предыдущих практик не переписываются.

## Критерии поведения

1. Поле имеет видимую подпись, описание ограничения и счётчик.
2. Для пустого или слишком длинного diff показана русская ошибка,
   фокус возвращается в поле, HTTP-запрос не отправляется.
3. После отправки видны загрузка и недоступная кнопка отправки.
   Двойной клик, Enter и повторный submit не создают второй запрос.
4. Пока идёт запрос, поле доступно для чтения, но не редактирования.
5. При HTTP 200 комментарий виден в области результата. При пустом
   `comment` показано отдельное состояние, а не ложный «успех».
6. При сетевой/серверной ошибке точный исходный diff остаётся в поле,
   показана понятная ошибка и доступна повторная попытка.
7. Строка, не соответствующая контракту ответа, считается ошибкой.
8. Диалог «Как получить diff» открывается с клавиатуры, закрывается
   кнопкой и Escape; после закрытия фокус возвращается к вызвавшей кнопке.
9. Основной сценарий доступен с клавиатуры; фокус явно обведён.
10. На ширине 390 px карточки стоят друг под другом, горизонтального
    скролла страницы нет; длинный код переносится внутри результата.

## Дизайн

Material UI: Button, Card, TextField, Dialog, Alert, Skeleton,
Typography, Chip. Одна тема: тёплый светлый фон, белые поверхности,
тёмный текст, синий акцент, шаг отступов 8 px. Моноширинный шрифт
только для diff и примеров кода. Текст и состояния совпадают с прототипом.
