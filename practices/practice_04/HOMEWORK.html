Б. Skill: создание и проверка — 2 балла

Skill имеет обязательный SKILL.md с точным условием применения, последовательностью чтения файлов, проверками границ и запретом расширять контракт посторонними фичами. Отдельный скрипт не добавлялся: содержательная автоматизация уже собрана в корневом make check, а skill задаёт воспроизводимый способ её применения и формат доказательств. 

quick_validate.py .opencode/skills/review-api-contract
→ Skill is valid!

opencode debug skill
→ review-api-contract найден по проектному пути

opencode run -m ollama/itmo-agent-local ...
→ skill(review-api-contract), затем make check

make check
→ All checks passed; Practice 1 OK; Practice 2 OK; API 6/6; MCP 3/3

Skill вызван через OpenCode с локальной моделью ollama/itmo-agent-local; VseLLM не использовался. Модель сама выполнила make check, но затем ошибочно назвала ожидаемую ошибку MCP-теста для 20 001 символа сбоем git diff --check, хотя эту команду не запускала. Повторяющийся ответ был остановлен, а git diff --check выполнен отдельно с exit code 0.

В. Собственный MCP — 2 балла

Tool check_review_diff(diff) проверяет вход до обращения к API. Он принимает непустую строку длиной не более 20 000 символов и возвращает длину, ожидаемый HTTP-статус и разрешение на вызов LLM. Ошибки передаются клиенту как MCP tool result с isError=true. Реализация использует официальный Python SDK MCP версии 2.3.0. 

tools/list
→ ["check_review_diff"]

tools/call {"diff": "test"}
→ {"accepted": true, "length": 4, "http_status": 200,
   "llm_call_allowed": true}

tools/call {"diff": "x" × 20001}
→ isError=true, "diff has 20001 characters; maximum is 20000"

tools/call {"diff": 123}
→ isError=true (ввод отклонён схемой tool)

Результат: 3 из 3 MCP-сценариев прошли.
