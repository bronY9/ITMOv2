# Рефлексия

Больше всего помог маршрут в `AGENTS.md`: он заставил сначала прочитать
исходный diff, ADR, CASE и прежние тестовые сценарии. Благодаря этому контракт
A сохранился, а для B был найден точный код HTTP 413 из `API-1`. Единая
команда `make check` тоже оказалась полезнее набора обещаний: после каждого
изменения она одинаково проверяла стиль, старые практики, API и MCP.

Главная помеха состояла в том, что исходники приложения сначала существовали
только как учебный `TRAINING_PR.diff`. Позже ранние разделы README остались в
этом состоянии и начали противоречить появившейся реализации. Новый чат,
прочитав handoff, нашёл это расхождение; после этого документация была
обновлена. Доступ к локальному Ollama из изолированной команды сначала не
работал, но после разрешённого локального запуска OpenCode вызвал skill через
`ollama/itmo-agent-local` без VseLLM.

Вмешаться пришлось дважды. Сначала предварительное ожидание HTTP 422 для
слишком длинного `diff` было исправлено на HTTP 413 после чтения CASE. Затем
субагент воспроизвёл HTTP 500 для успешного запроса: тесты скрывали
неработающий глобальный LLM подменой состояния. Глобальная подмена была
удалена, а `ReviewService` стал явно передаваться в `create_app`; повторная
проверка дефектов не нашла.

Skill оказался удобен как короткий воспроизводимый маршрут к актуальным
файлам и проверкам. Собственный MCP оказался полезен как машиночитаемая
граница перед API: клиент получает структурированный успешный результат, а
пустой, нестроковый или слишком длинный ввод превращается в контролируемую
ошибку tool. При этом MCP не заменяет тесты самого FastAPI и не доказывает
работу живого ASGI-сервера.

Локальная модель успешно загрузила skill и выполнила `make check`, но затем
перепутала ожидаемую ошибку теста для 20 001 символа с результатом
`git diff --check`, который она не запускала. Пришлось остановить повторяющийся
ответ и выполнить `git diff --check` отдельно. Этот эпизод показал, почему
журнал команд и exit code надёжнее итогового пересказа модели.

Кроме того, OpenCode при запуске автоматически добавил `$schema` в переданный
ему отслеживаемый локальный конфиг practice_03. Проверка `git status` обнаружила
побочный эффект, после чего строка была удалена и lab/demo снова остались без
изменений.

Непроверенными остаются запуск приложения с настоящим LLM и журнал GitHub
Actions для текущих незакоммиченных изменений. Эти пункты отделены от уже
полученных результатов, чтобы отчёт не смешивал факты с планами.
