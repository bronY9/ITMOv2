# Рефлексия: две команды и два SDD-фреймворка

## Что пришлось согласовать двум командам

Независимые черновики совпали в цели, но оставили четыре настоящих вопроса на границе:

1. UI не знал, является ли preview разрешением на ревью. Решили, что нет: ревью
   всегда проверяет данные заново.
2. UI хотел понятные ошибки, а логика не хотела закреплять внутреннюю JSON-схему.
   Контрактом стали HTTP-статусы; тексты принадлежат UI.
3. Нужно было одинаково понимать длину Unicode. Выбрали code points и сохранили
   сервер источником истины.
4. В логике не были определены устаревший preview и повторные нажатия. UI добавил
   инвалидацию результата после редактирования и блокировку дублей.

Эти решения появились до кода и видны в сравнении `before/` с финальными
`ui-spec.md`, `logic-spec.md` и `contracts/shared-contract.md`.

## Сравнение OpenSpec и GitHub Spec Kit

| Критерий | OpenSpec | Spec Kit |
|---|---|---|
| Единица работы | change с delta-spec | feature с user stories |
| История решения | proposal, design, archive | constitution, spec, plan, tasks |
| Постоянные правила | `openspec/config.yaml` | project constitution |
| Проверка согласованности | strict validate | quality checklist + analyze + converge |
| Сильная сторона | компактный жизненный цикл изменения и синхронизация main specs | трассировка от пользовательской истории до контракта и задачи |
| Цена | меньше места для нескольких параллельных взглядов | больше документов и дисциплины |

OpenSpec оказался удобнее для небольшого изменения уже известного API: proposal и
delta-spec быстро показывают разницу, а archive делает её частью основной
спецификации. Spec Kit оказался понятнее именно для домашнего задания про две команды:
можно сохранить два исходных черновика, сформировать общий контракт, а затем явно
проверить покрытие требований задачами до реализации.

## Что получилось проверить фактически

- Preview применяет те же правила, но не вызывает LLM.
- Приоритет ошибки длины сохраняется для 20 001 пробельного символа.
- Настоящее ревью повторяет проверку и вызывает LLM один раз.
- Интерфейс безопасно показывает HTML-подобный комментарий как текст.
- Ошибка не стирает ввод; редактирование делает preview устаревшим.
- Двойное нажатие создаёт один запрос.
- Страница работает на ширине 320 px и имеет подпись, live-статус и alert.

## Что узнал

Общий контракт нужен не ради формальности: самые полезные решения находились не
внутри UI или API, а на их стыке. Spec Kit делает этот стык заметнее, а OpenSpec лучше
поддерживает дальнейшую жизнь уже принятого изменения. Для маленькой фичи я бы выбрал
OpenSpec; для работы нескольких команд с отдельными зонами ответственности — Spec Kit.
