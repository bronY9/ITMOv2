# Команда 2: черновик логики до согласования

**Создано**: 2026-10-22  
**Статус**: независимый черновик, код ещё не менялся

## Цель

Добавить отдельную проверку diff, которая применяет те же правила, что настоящее
ревью, но не обращается к `ReviewService` и LLM.

## Данные и правила

- Вход — JSON-объект с обязательным полем `diff`.
- `diff` обязан быть строкой и содержать хотя бы один непробельный символ.
- Строка длиной до 20 000 символов включительно допустима.
- Любая строка длиной больше 20 000 символов отклоняется до остальных проверок.
- Допустимый текст не обрезается и не нормализуется.
- Длина считается в Unicode code points.

## API-черновик

- `POST /api/reviews/validate` принимает `{"diff": string}`.
- Успех: HTTP 200 и `{"valid": true}`.
- Отсутствующее, нестроковое, пустое или только пробельное значение: HTTP 422.
- Любая строка длиннее 20 000 символов: HTTP 413.
- Тело ошибки остаётся внутренней деталью сервера.

## Алгоритм

1. Разобрать тело и проверить наличие строгой строки.
2. Проверить длину; при превышении вернуть 413.
3. Проверить наличие непробельного символа; при отсутствии вернуть 422.
4. Вернуть `{"valid": true}` без вызова сервиса и LLM.

## Совместимость

- `POST /api/reviews` сохраняет текущий успешный ответ `{"comment": string}`.
- Настоящее ревью самостоятельно повторяет проверку.
- MCP-контракт не меняется.
