# Команда 1: черновик UI до согласования

**Создано**: 2026-10-22  
**Статус**: независимый черновик, код ещё не менялся

## Цель

Дать пользователю одну понятную страницу, где он может вставить diff, проверить его
до запуска ревью и затем получить комментарий.

## Экран и действия

- Многострочное поле с видимой подписью «Diff».
- Счётчик введённых символов.
- Кнопка «Проверить diff».
- Кнопка «Запустить ревью».
- Область статуса, ошибки и результата ревью.

## Состояния

1. Начальное — поле пустое, результат отсутствует.
2. Редактирование — счётчик обновляется, прежняя проверка становится неактуальной.
3. Проверка — повторные действия временно недоступны.
4. Проверка успешна — виден положительный статус.
5. Ревью выполняется — повторный запрос недоступен.
6. Ревью успешно — комментарий показан как обычный текст.
7. Ошибка валидации — введённый diff сохранён, понятна причина.
8. Preview недоступен — пользователь видит отдельное сообщение.
9. Сетевая или серверная ошибка — можно исправить данные или повторить запрос.

## Пользовательские сценарии

### UI-1 — Предварительная проверка

**Given** пользователь ввёл diff, **when** он выбирает «Проверить diff», **then**
страница сообщает, можно ли отправлять этот diff дальше, не запуская ревью.

### UI-2 — Запуск ревью

**Given** пользователь ввёл допустимый diff, **when** он выбирает «Запустить ревью»,
**then** страница показывает текст комментария.

### UI-3 — Исправление ошибки

**Given** страница показала ошибку, **when** пользователь меняет текст, **then**
старый результат проверки больше не выглядит актуальным, а введённый текст не теряется.

## Доступность

- Статус и ошибка объявляются вспомогательным технологиям.
- Фокус и подписи элементов видимы.
- Состояния различимы не только цветом.
- На ширине 320 px элементы остаются доступными.
- Enter в поле добавляет новую строку и не отправляет форму.

- Как считать Unicode-символы и является ли счётчик источником истины?
