# Команда 1: согласованная спецификация UI

**Основа**: `before/ui-spec.md`  
**Контракт**: `contracts/shared-contract.md`  
**Статус**: согласовано до реализации

## Изменения после согласования

- Зафиксированы три вызова и точные успешные ответы.
- UI принимает решения по HTTP-статусу, а не по форме тела ошибки.
- Preview не обязателен перед ревью и устаревает после любого изменения поля.
- Счётчик использует Unicode code points, сервер остаётся источником истины.

## Экран

Одна страница содержит заголовок, короткое объяснение, многострочное поле `Diff`,
счётчик `N / 20 000`, кнопки «Проверить diff» и «Запустить ревью», статус,
сообщение об ошибке и текст результата.

## Состояния и переходы

| Состояние | Вход | Выход |
|---|---|---|
| Начальное | Страница открыта | Пользователь вводит текст |
| Редактирование | Поле изменено | Preview или ревью |
| Проверка | Нажата проверка | Успех или ошибка |
| Preview успешен | Получен HTTP 200 | Изменение текста или ревью |
| Ревью выполняется | Нажато ревью | Комментарий или ошибка |
| Результат | Получен комментарий | Новое редактирование или запрос |
| Ошибка | 4xx, 5xx или сеть | Исправление или повтор |

## Условия приёмки UI

1. Страница загружается по `GET /` и работает без отдельной настройки CORS.
2. Счётчик обновляется по Unicode code points и показывает границу 20 000.
3. Preview отправляет исходное значение без `trim` или иной нормализации.
4. HTTP 200 preview показывает, что diff допустим, но не блокирует прямой запуск ревью.
5. HTTP 422, 413, 404 и 5xx/сеть показывают согласованные сообщения.
6. После изменения поля положительный preview больше не выглядит актуальным.
7. Пока любой запрос выполняется, обе кнопки не создают повторных запросов.
8. Ошибка не очищает поле.
9. Комментарий вставляется через текстовое представление и не выполняет HTML.
10. Enter в textarea добавляет новую строку.
11. Подпись поля, фокус, live-статус и alert-ошибка доступны с клавиатуры и
    вспомогательных технологий.
12. Интерфейс остаётся пригодным на ширине 320 px.
