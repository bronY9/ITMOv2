# Практика 7.2 · автоисправление по GitHub Issue

n8n получает GitHub-событие с меткой `bug`, предлагает исправление, создаёт ветку и PR, проверяет опубликованный diff второй моделью и сливает проверенный коммит. **Ветка, PR и merge находятся только в личном репозитории `bronY9/ITMOv2`. Цель слияния — `bronY9/ITMOv2:main`.**

В [условии задания на +10](../../README.md#задача-на-сверхрезультат-10-баллов) основная ветка названа `master`. В `bronY9/ITMOv2` эту роль выполняет `main`, поэтому workflow открывает PR с `base: main` внутри этого репозитория. Входной фильтр сверяет имя репозитория, а ноды создания и слияния PR используют GitHub API по пути `/repos/bronY9/ITMOv2/pulls`. Общий репозиторий курса `ai-course-avito/ITMOv2` остаётся источником условия.

Пример ограничен одной функцией в `practices/practice_07.2/autofix_demo/is-weekend.mjs`. В исходной версии воскресенье `0` ошибочно считалось будним, а `7` — выходным.

Рабочая копия опубликована в [n8n](https://n8n-itmo.cyrweb.ru/workflow/QHDPEwd2gzjhL4Ct).

1. Импортировать `autofix.json` в n8n и выбрать существующие GitHub и OpenAI credentials у соответствующих нод. GitHub Trigger слушает Issues. Сценарий обработки Issues из основной части 7.2 проставляет метку `bug`.
2. Успешный прогон использовал исходную версию файла из [подготовительного PR №13](https://github.com/bronY9/ITMOv2/pull/13) и Issue с заголовком и описанием из `issue.txt`. Сейчас в `bronY9/ITMOv2:main` уже лежит исправленная версия. Для защиты открыть сохранённое выполнение №9099.
3. Открыть **Executions**, затем выходы «AI предлагает исправление», «Проверить правку и граничные дни», «Создать ветку Issue», «Открыть Pull Request», «Независимое AI-ревью», «Подтвердить merge». В GitHub показать ту же ветку, строку diff, опубликованное ревью и состояние PR.

Защита слияния проверяет 13 входов, один затронутый файл и одну строку, SHA опубликованного коммита, результат отдельного ревью и состояние `main`. Ответ модели обрабатывается как данные. GitHub выполняет свои обычные проверки слияния. Ветка попытки включает номер Issue и ID выполнения. При повторной попытке это сохраняет историю предыдущего PR. После исправления в `main` проверка исходного снимка останавливает дальнейшие попытки.

Локальная проверка логики нод и блокировки слияния:

```sh
node test-autofix.mjs
```

Этот тест проверяет логику на известных ответах. Реальное выполнение в n8n и состояние PR подтверждаются отдельно.

- [Issue №15](https://github.com/bronY9/ITMOv2/issues/15) описывает ошибку. Обработчик Issues поставил метку `bug`.
- [Выполнение n8n №9099](https://n8n-itmo.cyrweb.ru/workflow/QHDPEwd2gzjhL4Ct/executions/9099) сформировало правку, проверило 13 входов, создало ветку `practice072-autofix/issue-15-9099` и запустило отдельное ревью. Последняя нода вернула `merged: true`.

Исходная ветка `practice072-autofix/issue-15-9099` и целевая ветка `main` принадлежат `bronY9/ITMOv2`. n8n автоматически слил этот PR в `bronY9/ITMOv2:main`. Merge-коммит имеет SHA `886ccf005ea683b90841853c50360b010b4bc1b8`.
- [Первый запуск №9092](https://n8n-itmo.cyrweb.ru/workflow/QHDPEwd2gzjhL4Ct/executions/9092) остановился после ревью. Он оставил [PR №16](https://github.com/bronY9/ITMOv2/pull/16) без слияния, поскольку строгий разбор не принял вердикт с пояснением. После уточнения формата решение берётся из последней строки. `BLOCK` или ответ без явного итогового вердикта по-прежнему останавливает слияние.
