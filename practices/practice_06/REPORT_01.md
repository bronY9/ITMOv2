# Отчёт 1. Атаки на исходный сервис

## Методика

Исходный `Shop.dispatch` проверен прямыми запросами к одноразовому экземпляру Mini Shop. Все
данные синтетические, атаки не выходили за `127.0.0.1` и временный sandbox. Для каждого случая
фиксировались статус и наблюдаемый результат.

## Найденные проблемы

| ID | Риск | Воспроизведение на исходной версии | Наблюдаемый результат |
|---|---|---|---|
| F01 | Critical | `GET /profile?id=2` без токена | `200`, полный профиль Bob |
| F02 | High | `GET /search?q=' OR 1=1 -- ` | SQL-инъекция вернула оба профиля |
| F03 | High | `GET /orders` без токена | `200`, заказы Alice и Bob |
| F04 | High | Alice: `POST /orders {"product":"chair","price":1}` | Заказ создан по цене `1` вместо `5000` |
| F05 | Critical | `GET /admin/export` только с `X-Role: staff` | `200`, экспорт всех профилей без staff-сессии |
| F06 | High | Alice: `GET /files?user=bob&path=receipt.txt` | Получен чек Bob |
| F07 | Critical | Alice: `GET /files?user=../private&path=operator-note.txt` | Получен `TEST_ONLY_OPERATOR_SECRET` |
| F08 | High | Отзыв `<script>TEST_XSS</script>`, затем `/reviews/view` | Скрипт вставлен в HTML без экранирования |
| F09 | Critical | `GET /debug/logs` без токена | Логи содержат пароли, токены, тела и заголовки |
| F10 | High | Alice: `/assistant/context?order_id=2` | В контекст попал чужой заказ Bob |
| F11 | Critical | `/assistant/execute` без токена, tool=`export_profiles` | `200`, профили экспортированы |
| F12 | Critical | `/assistant/execute` без токена, `read_file(private/operator-note.txt)` | Служебная заметка раскрыта |
| F13 | Critical | Вредоносный отзыв просит `delete_tree('.')`; решение отправлено executor-у | `200 {"deleted":"."}`, файлы стенда удалены |
| F14 | Medium | Некорректный JSON или отсутствующие поля | `500` раскрывал тип и текст исключения |

## Prompt injection до исправления

Исходный контекст одновременно называл `delete_tree` и помещал отзыв сразу после системной
инструкции без границы недоверенных данных. Точный вход сохранён в
`evidence/before/assistant-context.txt`.

Независимо от поведения конкретной LLM принудительная передача опасного решения доказала
главную ошибку доверия: сервер сам разрешал разрушительное действие. Результат сохранён в
`evidence/before/forced-delete-result.json`.

## Причины

1. Аутентификация применялась только к созданию заказа.
2. Проверки владельца отсутствовали, а роль принималась из клиентского заголовка.
3. SQL строился строковой интерполяцией.
4. Цена, пути к файлам и AI tool полностью контролировались клиентом или моделью.
5. Данные отзывов смешивались с инструкциями LLM.
6. Вывод HTML и журналирование не учитывали секреты.

Физический выход из временного sandbox не найден: `sandbox.py` корректно проверяет resolved path
и symlink. Этот файл не изменялся.
