## Границы изменения

- Фича A: добавить входную схему запроса с обязательным строковым непустым полем `diff` для `POST /api/reviews`.
- Сохранить успешное поведение: валидный `diff` передаётся в `ReviewService`, ответ остаётся `{"comment": <строка>}`.
- Обновить проверки, которые описывают прежний `KeyError`/HTTP 500: после фичи A невалидное тело должно отклоняться до вызова LLM контролируемой клиентской ошибкой FastAPI.
- Не реализовывать в A лимит 20 000 символов, редактирование секретов, таймаут/обработку ошибок LLM, аутентификацию, изменение формата ответа или фичу B.
- Не изменять учебный снимок `practices/practice_01/TRAINING_PR.diff`.

## Условие приёмки A

- `{"diff": "test"}` вызывает LLM один раз и возвращает HTTP 200 с `{"comment": <строка>}`.
- Отсутствующий `diff`, нестроковый `diff` и пустая строка отклоняются как ошибка клиента; LLM не вызывается.
- Unit-, integration- и E2E-проверки отражают новое поведение и проходят.

## Команды проверки

Из корня репозитория:

```bash
make lint
make step1
make step2
make test
make check
```

`make check` объединяет lint фичи A и существующие проверки. Все команды существуют в корневом `Makefile`. Если в репозитории появятся исходники приложения и отдельная команда их тестирования, сначала добавьте её в этот файл, затем используйте как обязательную проверку фичи A.
